# AI Forward Engineer — Professional Direction Research

## Research Question

What does an "AI Forward Engineer" actually do? What tools do they use? What
skills do they need? What makes a portfolio in this field credible?

---

## Role Definition

An AI Forward Engineer sits at the intersection of software engineering and
applied AI. They are not ML researchers — they don't train models from scratch.
They are builders who:

- Integrate LLMs and AI APIs into real applications
- Design prompting systems, agent loops, and orchestration pipelines
- Build retrieval-augmented generation (RAG) systems
- Evaluate and validate AI output quality
- Create developer tooling that makes AI more usable
- Work with product teams to identify where AI creates real value

### Real Job Titles in This Space
- AI Engineer
- LLM Engineer
- ML Platform Engineer
- Applied AI Engineer
- AI Product Engineer
- Prompt Engineer (entry-level adjacent)

## What the Field Actually Values

Based on research into job listings, industry writing, and the professor's
framework:

### 1. Engineering Fundamentals First
AI Forward Engineers are engineers first. They need:
- Strong programming skills (Python primary, TypeScript secondary)
- Comfort with APIs, data structures, systems design
- Version control, CI/CD, deployment experience
- The ability to read documentation and debug independently

### 2. AI API Literacy
They must understand:
- How to call OpenAI, Anthropic, Cohere, and similar APIs
- Token counting, context windows, rate limits
- Prompt engineering patterns (zero-shot, few-shot, chain-of-thought)
- How embeddings work conceptually
- What RAG is and when it's the right solution

### 3. Orchestration Thinking
The field is moving toward systems where multiple AI calls work together:
- LangChain / LangGraph for agent workflows
- Tool use / function calling
- Memory systems (short-term, long-term, semantic)
- Multi-model pipelines (routing, fallbacks, ensemble approaches)

### 4. Judgment Over Raw Output
The most valued engineers in this space have:
- The ability to evaluate AI output critically
- Clear criteria for "good enough vs. not good enough"
- An understanding of when AI is and isn't the right tool
- Verification habits (tests, evals, monitoring)

## Portfolio Signals That Matter

Researched from blog posts, hiring manager commentary, and engineer portfolios:

### What Makes a Junior AI Portfolio Credible

1. **Evidence of intentional AI use, not accidental use**
   - A prompt engineering lab (documented, not random)
   - Written evaluations of AI output ("this worked because..., this failed because...")

2. **At least one end-to-end project**
   - Not just a wrapper around an API
   - Something with a clear problem, a designed solution, and evidence that it works

3. **Documentation habit**
   - READMEs that explain the *why*, not just the *what*
   - Specs, plans, or design documents show you think before you build

4. **Honest self-assessment**
   - Claiming "expert in TensorFlow" when you've run one tutorial is a red flag
   - Saying "learning Python — here's what I've built so far" is credible

5. **A clear direction statement**
   - Not "I want to work in AI" (too vague)
   - "I want to build the orchestration layer that makes LLMs reliable in
     production" (specific and research-grounded)

## How This Research Shaped the Portfolio

| Research Finding | Portfolio Decision |
|---|---|
| Engineers are evaluated on judgment, not tool fluency | Honest skill levels instead of claimed mastery |
| Documentation habit is a signal | Writing 9 spec documents before building |
| End-to-end projects matter more than tutorials | Prompt Lab as an in-progress real project |
| Direction specificity matters | "AI Forward Engineer" not just "interested in AI" |
| Verification discipline is valued | Quality gates in every phase spec |
